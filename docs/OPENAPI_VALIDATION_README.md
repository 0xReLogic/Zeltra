## 🚨 Critical Findings

### The OpenAPI specification (`contracts/openapi.yaml`) is significantly outdated!

**What happened:**
- Backend was refactored to use organization-scoped routes
- Old unscoped routes were replaced with `/organizations/{org_id}/...` pattern
- OpenAPI spec was not updated to reflect these changes

**Impact:**
- 48 backend routes are not documented in OpenAPI (63% of routes)
- 38 routes in OpenAPI don't exist in backend (will return 404)
- Frontend developers following OpenAPI will call non-existent endpoints

**Example:**
```
❌ OpenAPI says:     GET /accounts
✅ Backend actually: GET /organizations/{org_id}/accounts
```

## 🔧 For Backend Developers

### Immediate Actions Needed

1. **Update OpenAPI Spec**
   - Add all 48 missing org-scoped routes
   - Remove or mark as deprecated the 38 old unscoped routes
   - Add the missing `/health` endpoint

2. **Fix Schema Mismatches**
   - Standardize field names (e.g., `subtype` vs `account_subtype`)
   - Document all optional fields
   - Add missing fields like `description`, `allow_direct_posting`

3. **Automate Schema Generation**
   - Consider using `utoipa` crate to generate OpenAPI from Rust code
   - Add CI checks to prevent future drift
   - Set up contract testing (Pact/Dredd)

### Long-term Improvements

1. **Code-first approach** - Generate OpenAPI from code annotations
2. **Automated testing** - Contract tests to catch mismatches
3. **Version management** - Clear versioning strategy for API changes
4. **Documentation process** - Update OpenAPI as part of PR requirements

## 📖 How This Was Created

This analysis was generated by:

1. **Extracting backend routes** from Rust source code (`backend/crates/api/src/routes/*.rs`)
2. **Parsing OpenAPI spec** from `contracts/openapi.yaml`
3. **Comparing routes** - Method + path matching
4. **Analyzing schemas** - Field-level comparison of request/response types
5. **Manual verification** - Spot-checking key endpoints and types

The validation scripts used are available in `/tmp/` on the build server.
